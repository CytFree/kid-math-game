# 交互式数学操作物 — 点击放置学加减法

**日期**: 2026-05-26 | **状态**: 设计中 | **范围**: Lv.1-6 题目可视化

## 背景

当前 Lv.1-6 的题目可视化区域（`.q-visual` / `#qVis`）由系统自动渲染 emoji
图标：加法显示两组图标（绿+蓝），减法显示正常图标 + 半透明图标。小朋友
只需看图标、选答案，缺少动手操作环节。

## 目标

将可视化区域改为**交互式操作区**，小朋友自己动手放置/移除 emoji，
在操作过程中理解"加"和"减"的具象含义。

## 核心交互

### 通用规则

- **来源区**：卡片上方或操作区上方，显示 10 个 emoji（对应题目的物品图标）
- **点击来源区 emoji** → 该 emoji 跳到当前活跃的放置行，来源区该位置变灰/消失
- **点击已放置的 emoji** → emoji 回收回来源区（撤销）
- **数字算式保留**在操作区下方（`#qEq`，不变）
- **自由探索**，不强制校验数量是否正确
- 答案选项（`#qOpts`）始终可用

### 加法流程（两行放置）

```
来源区: 🐟🐟🐟🐟🐟🐟🐟🐟🐟🐟

第1行 [放 3 个]:  🐟 🐟 🐟        ← 点击放置
第2行 [放 2 个]:  🐟 🐟            ← 点击放置

算式:  3  +  2  =  ?
```

1. 初始：两行都为空，虚线边框，灰色提示文字
2. 第一行活跃（蓝色边框高亮），点击来源区放置 emoji
3. 第一行放好（不强制校验），切换到第二行活跃（绿色边框高亮）
4. 两行都可以随时点击 emoji 收回

**行切换策略**：自动检测。当第 1 行数量到达目标数字时，自动高亮第 2 行。
但小朋友也可以直接点第 2 行放置（此时第 1 行自动失活）。

### 减法流程（一行，自动切换）

```
阶段一 - 放置:
来源区: 🦴🦴🦴🦴🦴🦴🦴🦴🦴🦴
行:     🦴 🦴 🦴 🦴 🦴          ← 放 5 个

阶段二 - 减除（自动切换）:
行:     🦴 🦴 🦴 🦴 🦴          ← 点掉 2 个
              ✕     ✕

结果:   🦴 🦴 🦴                 ← 还剩 3 个
算式:   5  −  2  =  ?
```

1. **阶段一（放置模式）**：蓝色边框，提示"放 X 个"
2. 当放置数量达到第一个数字时 → **自动切换**到阶段二
3. **阶段二（减除模式）**：边框变红色，提示变为"点掉 X 个"
4. 点击 emoji 使其变半透明/消失（带缩小动画）
5. 被点掉的 emoji 可以再点回来（撤销减除）
6. 完成减除后，边框变绿色，提示变为"还剩 X 个"

### 模式切换提示

- 来源区上方显示当前模式提示
- 加法："先放第 1 行（3 个），再放第 2 行（2 个）"
- 减法阶段一："放 5 个骨头"
- 减法阶段二："现在点掉 2 个 → 理解'减'就是拿走"

## HTML 结构变更

### 替换 `#qVis` 内容

```html
<!-- 原: <div class="q-visual" id="qVis"></div> -->
<!-- 新: -->
<div class="q-manipulative" id="qManip">
  <!-- 模式提示 -->
  <div class="qm-hint" id="qmHint"></div>
  <!-- 来源区 -->
  <div class="qm-source" id="qmSource"></div>
  <!-- 放置行(加法2行，减法1行) -->
  <div class="qm-rows" id="qmRows"></div>
  <!-- 减法模式指示器 -->
  <div class="qm-mode" id="qmMode" style="display:none"></div>
</div>
```

### CSS 新增样式

- `.q-manipulative` — 整体容器
- `.qm-hint` — 模式提示文字
- `.qm-source` — 来源区（emoji 池），flex-wrap 布局
- `.qm-source .si` — 来源区每个 emoji，点击触发放置
- `.qm-source .si.used` — 已被取走的 emoji（opacity: 0.2）
- `.qm-row` — 放置行容器，虚线边框，min-height
- `.qm-row.active` — 当前活跃行（蓝色发光边框）
- `.qm-row.subtract-mode` — 减法模式（红色边框）
- `.qm-row .ri` — 放置行内的 emoji
- `.qm-row .ri.removed` — 减法中被点掉的 emoji（缩小 + 半透明）

## JS 逻辑新增

### 函数

| 函数 | 职责 |
|------|------|
| `initManip(q)` | 根据题目初始化操作区（加法/减法分支） |
| `renderSource(emoji, total)` | 渲染来源区的 10 个 emoji |
| `renderRows(op, nums)` | 渲染放置行（加法 2 行 / 减法 1 行） |
| `placeItem(rowIdx)` | 从来源区取一个 emoji 放到指定行 |
| `removeItem(rowIdx, itemIdx)` | 从放置行收回一个 emoji 到来源区 |
| `switchToSubtract()` | 减法：放置完成 → 切换到减除模式 |
| `undoSubtract(itemIdx)` | 减法减除模式中恢复被点掉的 emoji |

### 集成点（修改现有函数）

| 现有函数 | 变更 |
|----------|------|
| `nextQ()` L384 | `if(S.level>=7)` 分支不变；else 分支改为调用 `initManip(q)` 替代原有的 emoji 渲染 |
| `animateQ()` | 移除或简化，操作区替代了原有的动画逻辑 |
| `chk()` | 不变，答案选择逻辑完全独立于操作区 |

### 状态管理

```javascript
var MS = {
  op: '',          // '+' | '-'
  emoji: '',       // 当前题目的 emoji
  nums: [],        // [a, b]
  rows: [],        // [[row1 items], [row2 items]]  加法; [[row1 items]] 减法
  sourceUsed: 0,   // 来源区已取走数量 (max 10)
  stage: 'place',  // 'place' | 'subtract' (减法专用)
  subtractDone: 0  // 减法中已点掉的数量
};
```

## 降级与兼容

- Lv.7 及以上的分解树枝图（`renderDecompTree`）不受影响
- 故事模式、冒险模式、每日任务等所有出题场景统一使用新操作区
- 移动端触摸事件与桌面端 click 事件统一处理
- 来源区 emoji 尺寸 36px（手机）/ 40px（平板），确保小手指可点击

## 不做的事

- 不引入拖拽（拖拽在移动端体验差、实现复杂）
- 不校验放置数量是否正确（自由探索）
- 不改变答案选项的交互逻辑
- 不改动 Lv.7 的分解树枝图
- 不改变后端/存储逻辑（纯前端 UI 变更）
